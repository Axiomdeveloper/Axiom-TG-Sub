# Axiom TG — ساب خودکار V2Ray از کانال‌های تلگرام

[![auto-update](https://img.shields.io/badge/update-every_5h-00e0a4)](#)
[![retention](https://img.shields.io/badge/retention-48h-7c5cff)](#)
[![channels](https://img.shields.io/badge/channels-8-0aa3ff)](#)

هر **۵ ساعت**، آنتی‌اکشن (GitHub Action) کانفیگ‌های **۲۴ ساعت اخیر** هشت کانال تلگرامی را می‌خواند، نام همه را به
**`Axiom TG`** تغییر می‌دهد و در قالب یک **Subscription** واحد منتشر می‌کند. کانفیگ‌ها پس از **۴۸ ساعت** خودکار از
آرشیو حذف می‌شوند. آمار (کانال‌به‌کانال، مجموع، تعداد کاربران ساب) بین دو مارکر پایین به‌صورت خودکار بازنویسی می‌شود.

Every 5 hours, a GitHub Action scrapes the last 24 hours of 8 Telegram channels, renames every V2Ray config to
**Axiom TG**, and publishes a single rolling subscription (48h retention). Stats below are auto-regenerated.

## معماری / Pipeline

```
 .github/workflows/axiom-update.yml   cron: "7 */5 * * *"  (هر ۵ ساعت)
                │
                ▼
 scripts/fetch_configs.py
   ├─ t.me/s/<channel>  → پست‌های ۲۴ ساعت اخیر
   ├─ استخراج vless/vmess/trojan/ss/ssr/tuic/hy2/...
   ├─ ری‌نیم → #Axiom TG + ps در VMess
   ├─ آرشیو ۴۸ ساعته (history/archive.json) + حذف قدیمی‌ها
   ├─ sub/axiom_sub.txt (base64) + sub/axiom_plain.txt
   ├─ stats.json  ← مجموع، کانال‌به‌کانال، کاربران
   └─ README stats block (این فایل)
                │
                ▼ (اختیاری)
 POST <APP_URL>/api/ingest  ──►  داشبورد Next.js (Postgres)
                                  ├─ /api/sub    ساب زنده + شمارش کاربران
                                  ├─ /api/stats  JSON + shields badge
                                  └─ صفحه‌ی اصلی فارسی با آمار زنده
```

## راه‌اندازی روی گیت‌هاب خودتان — قدم‌به‌قدم / Deploy guide

### شمای کلی / Modes

| حالت | چه چیزی می‌گیرید | پیش‌نیاز |
|---|---|---|
| **A — GitHub Pages (پیشنهادی!)** | داشبورد قشنگ روی `https://<USER>.github.io/<REPO>/` + ساب خام گیت‌هاب + جدول آمار در README | فقط خود مخزن — **بدون هاست و دیتابیس** |
| **B — کامل** | حالت A + داشبورد Next.js زنده با **شمارش لحظه‌ای کاربران** | مخزن + هاست Node + Postgres |

> حالت A همان طراحی داشبورد اصلی را دارد؛ تنها تفاوت: چون GitHub Pages استاتیک است، «کاربران ساب» در حالت A صفر می‌ماند
> (روی لینک خام گیت‌هاب امکان شمارش نیست). هر وقت خواستی، داشبورد Next.js را اضافه کن و آمار کاربران در Pages روشن می‌شود.

### روشن‌کردن داشبورد روی GitHub Pages (فقط دو کلیک)

1. کارهای گام ۱ و ۲ پایین را انجام بده (فورک + Enable Actions + اولین Run workflow).
2. **Settings → Pages** → بخش **Build and deployment** → Source: **Deploy from a branch**
   → Branch: **`main`**، پوشه: **`/docs`** → **Save**.
3. حدود یک دقیقه بعد، بالای همان صفحه لینک سایت نوشته می‌شود: `https://<USER>.github.io/<REPO>/`
   (Action هم هر بار لینکش را در بلوک «داشبورد زنده» همین README به‌روز می‌کند).

تمام! هر ۵ ساعت، هم ساب و هم این صفحه‌ی داشبورد خودکار تازه می‌شوند. برای لینک سفارشی (دامنه‌ی شخصی) داخل Pages هم می‌توان گذاشت — ساب تغییر لازم ندارد و خام گیت‌هاب می‌ماند.

دو حالت ممکن بود؛ جزئیات کامل هر دو:

| حالت | چه چیزی می‌گیرید | پیش‌نیاز |
|---|---|---|
| **A — ساده** | ساب روی لینک خام گیت‌هاب + جدول آمار در README (شمار کاربران = صفر) | فقط خود مخزن |
| **B — کامل (پیشنهادی)** | حالت A + داشبورد فارسی + شمارش زنده‌ی کاربران ساب | مخزن + هاست Node + Postgres |

### گام ۱ — مخزن را بسازید (هر دو حالت)

1. روی **Fork** بزنید، یا با **Download ZIP → Push** فایل‌ها را در یک مخزن جدید بگذارید (پوشه‌ی `.github/workflows` حتماً همراه‌شان باشد).
2. ریپو باز شود: تب **Actions** — اگر نوار زرد رنگ دیدید روی **I understand my workflows, go ahead and enable them** کلیک کنید.
3. ورک‌فلو: `.github/workflows/axiom-update.yml` خودش `permissions: contents: write` دارد تا بات بتواند کامیت کند.
   اگر کامیت با خطای `Permission denied` مواجه شد: **Settings → Actions → General → Workflow permissions → Read and write permissions** را روشن کنید.

### گام ۲ — اولین اجرای دستی (هر دو حالت)

**Actions → Axiom TG — auto-update subscription → Run workflow → Run workflow**
پس از حدود یک دقیقه:
- لِگ سبز شود، Step summary جدول کانال‌به‌کانال را نشان می‌دهد،
- یک کامیت خودکار از `axiom-tg-bot` می‌بینید: `sub/axiom_sub.txt`, `stats.json`, `history/archive.json` و جدول آمار همین README.

از این لحظه، حالت A تمام است — ساب شما:
`https://raw.githubusercontent.com/<YOUR_USER>/<REPO>/main/sub/axiom_sub.txt`
و خودکار هر ۵ ساعت تازه می‌شود.

### گام ۳ — دیپلوی داشبورد (فقط حالت B)

1. **Postgres** بسازید: [Neon](https://neon.tech) (رایگان) یا هر Postgres دیگر → رشته‌ی اتصال را بردارید.
2. **Next.js** را روی [Vercel](https://vercel.com) (`Import repository`) یا هر هاست Node دیپلوی کنید و این متغیرها را بگذارید:

   | متغیر | مقدار |
   |---|---|
   | `DATABASE_URL` | رشته‌ی اتصال Postgres |
   | `INGEST_SECRET` | یک رشته‌ی تصادفی بلند، مثلاً خروجی `openssl rand -hex 32` |
   | `TRACK_SALT` | رشته‌ی تصادفی دوم (نمک هش کاربرها — اختیاری) |
   | `NEXT_PUBLIC_REPO_URL` | آدرس مخزن گیت‌هاب (اختیاری — برای دکمه‌ی گیت‌هاب هدر) |

3. یک‌بار اسکیما را بسازید (روی کامپیوتر خود):
   ```bash
   git clone <repo> && cd <repo>
   DATABASE_URL="postgres://..." npx drizzle-kit push
   ```
   یا روی هاست مستقر، این دستور را یک‌بار اجرا کنید.
4. تست: `<APP_URL>/api/health` باید `{"ok":true,"db":true}` بدهد.

### گام ۴ — اتصال اکشن به داشبورد (فقط حالت B)

در مخزن گیت‌هاب: **Settings → Secrets and variables → Actions**:
- تب **Secrets → New repository secret** → نام: `INGEST_SECRET` ، مقدار: همان مقدار سرور (گام ۳).
- تب **Variables → New repository variable** → نام: `APP_URL` ، مقدار: مثل `https://axiom-tg.vercel.app`.

دوباره **Run workflow** بزنید — در لاگ باید خط `pushed to dashboard: HTTP 200 — users=…` دیده شود.
از این پس داشبورد واقعی است، `/api/sub` هر دریافت را می‌شمارد و شماره‌ی کاربران هم به README برمی‌گردد.

### گام ۵ — تست نهایی

- ساب وب: `<APP_URL>/api/sub` — Base64 برمی‌گردد، هدرهای `profile-title` و `profile-update-interval` دارد.
- JSON آمار: `<APP_URL>/api/stats` — Badge: `<APP_URL>/api/stats?badge=users`.
- در v2rayNG/Hiddify: Add subscription → هر دو نوع لینک (raw گیت‌هاب یا `/api/sub`) کار می‌کند → Update → کانفیگ‌های `Axiom TG` می‌آیند.

### عیب‌یابی / Troubleshooting

| مشکل | علت محتمل | حل |
|---|---|---|
| ورک‌فلو اصلاً اجرا نشد | Actions غیرفعال | گام ۱-۲ |
| `Permission denied` هنگام push | Workflow permissions فقط Read است | گام ۱-۳ |
| کانال `FAIL (no public messages)` | کانال پرایوت/حذف‌شده یا يوزرنیم غلط | اسکن بقیه ادامه دارد؛ یوزرنیم را در `scripts/fetch_configs.py` چک کنید |
| `users` همیشه 0 | کاربران از لینک raw گیت‌هاب استفاده می‌کنند (پرتابژ نقشه) یا `APP_URL`/`INGEST_SECRET` نادرست | گام ۴؛ لینک `/api/sub` را به کاربران بدهید |
| کامیت جدید نیامد | «no changes — sub is already fresh» یعنی چیزی عوض نشده (طبیعی است) | — |
| cron دقیق سر وقت نیست | تأخیر طبیعی GitHub زمان ساعت شلوغی | چند دقیقه تا نیم‌ساعت عادی است |

## نکات / Notes

- **تغییر فاصله‌ی به‌روزرسانی:** خط `cron: "7 */5 * * *"` در ورک‌فلو و مقدار `updateEveryHours` در `fetch_configs.py` — cron به UTC است («دقیقه‌ی ۷، ساعت‌های ۰/۵/۱۰/۱۵/۲۰ UTC»).
- **تغییر نام کانفیگ‌ها:** ثابت `BRAND` در `scripts/fetch_configs.py` (پیش‌فرض `Axiom TG`).
- **تغییر پنجره‌ها:** `SCAN_WINDOW = timedelta(hours=24)` و `RETENTION = timedelta(hours=48)`.
- **افزودن/حذف کانال:** لیست `CHANNELS` در `scripts/fetch_configs.py` و `src/lib/types.ts`.
- منبع داده صفحات عمومی `t.me/s/<channel>` است — **نه اکانت تلگرام لازم است، نه Bot Token، نه API key**؛ کانال بدون پیش‌نمایش عمومی `FAIL` می‌شود و بقیه متوقف نمی‌شوند.
- `history/archive.json` چرخه‌ی ۴۸ ساعته است؛ ویرایش دستی نکنید.
- رهگیری کاربران: فقط **هش نمک‌دار** IP+User-Agent ذخیره می‌شود، نه خود IP.
- این پروژه صرفاً پیوندهای عمومی منتشرشده را تجمیع و تغییر نام می‌دهد؛ مسئولیت استفاده بر عهده‌ی کاربر است.
